## ١. ما هو النظام

نظام إدارة الدورة المالية والتشغيلية لمقهى **مؤسسة ذا بوبليك هاوس** في جدة.
مستخدم واحد فعلياً (المالك)، وثلاثة أدوار مصمَّمة. لغة الواجهة عربية باتجاه
من اليمين إلى اليسار.

**ليس** نظاماً متعدّد المنشآت، ولا نظام محاسبة عاماً.

## ٢. المكوّنات الفعلية

| الطبقة | التقنية | ملاحظات |
|---|---|---|
| الواجهة | Next.js 16.3.4 (App Router) · React 19.2.8 · Tailwind v4 | مكوّنات خادم افتراضياً؛ ثلاثة مكوّنات عميل فقط |
| الخادم | Route Handlers في التطبيق نفسه | `runtime = "nodejs"` · لا خدمات مصغّرة |
| **الخدمات** | `src/services/*` | طبقة داخلية: المنطق هنا، والواجهات رقيقة |
| القاعدة | Neon Postgres عبر **Drizzle ORM** + `pg` | نقطة اتصال **مجمَّعة** إلزاماً |
| الهجرات | ملفات SQL في `drizzle/sql/` + `npm run db:migrate` | لا `drizzle-kit push` — يحتاج تفاعلاً ولا يترك أثراً |
| الدخول | Auth.js v5 + Google OAuth + جلسات في القاعدة | قائمة بيضاء صريحة |
| الملفات | Google Drive بصلاحية المستخدم نفسه | التطبيق لا يخزّن بايتات الملفات |
| الاستخراج | Gemini (`EXTRACTION_PROVIDER`) خلف واجهة قابلة للتبديل | البدائل: Claude · Ollama |
| النشر | Vercel | `apphosting.yaml` موجود لفايربيس وغير مستعمل |

**لا يوجد:** مهام خلفية · طوابير · webhooks · cron · تخزين مؤقّت موزَّع.
كل عملية تجري داخل طلب HTTP واحد، أو في سكربت يُشغَّل يدوياً.

## ٣. المبادئ التي تحكم الكود

هذه ليست شعارات — كلٌّ منها كُتب بعد عطل حقيقي:

1. **المال أعداد صحيحة بالهللات.** لا فاصلة عائمة في أي مسار.
2. **المجهول ليس صفراً.** `subtotal_minor` و`vat_minor` يقبلان `null`،
   والحالة الضريبية ثلاثية: `VALID | INVALID | UNKNOWN | NOT_APPLICABLE`.
3. **الخادم هو صاحب القرار.** مخرجات النموذج ومدخلات المتصفّح كلاهما
   **غير موثوق**، ويُعاد حساب كل نتيجة مالية على الخادم.
4. **الاستيراد منيع من التكرار.** بصمة للملف، وهوية لكل حركة، وقيد فريد
   في القاعدة — لأنّ الفحص في الكود يفلت من طلبين متزامنين.
5. **الدرايف لا يُمسّ.** لا دالة حذف ولا نقل ولا إعادة تسمية في `lib/drive.ts`.
6. **سجل التدقيق غير قابل للتعديل** — مفروض بمشغّلات في القاعدة لا باتفاق برمجي.
7. **الحساب في دوال خالصة.** `analytics` و`validation` و`insights` و`bank/match`
   لا تلمس القاعدة، فتُختبر كلّها.
8. **الصمت ممنوع.** الفشل يُعلَن ولا يُبتلَع؛ والفراغ خير من التخمين.

## ٤. تدفّق البيانات

```
المتصفّح ──┬─► POST /api/analyze ─► Gemini ─► استخراج منظَّم ─► مطابقة مورّد
           │                                          └─► فحص وتسمية ومجلد
           │        (لا يُكتب شيء بعد — معاينة فقط)
           │
           └─► POST /api/archive
                    │
                    ├─ DocumentService.assertNotDuplicate  (بصمة المحتوى)
                    ├─ ValidationService.assertMonthOpen   (قفل الشهر)
                    ├─ ValidationService.reviewForArchive  (إعادة الحساب)
                    ├─ DriveService.archiveToDrive         (رفع بلا استبدال)
                    └─ معاملة واحدة:
                         DocumentService.createDocument
                         InvoiceService.createInvoice + replaceLines
                         InvoiceService.createStatement
                         PaymentService.createPayment
                         DocumentService.recordFindings
                       ثم سجل تدقيق

كشف البنك ─► POST /api/bank-import
                ├─ بصمة الملف   (استيراد مكرّر يُعرف)
                ├─ هوية كل حركة (تكرار الصفوف يُعرف)
                ├─ قواعد التصنيف تسبق التخمين
                ├─ مطابقة بالمورّد ثم بمجموعات الفواتير
                └─ PaymentService.allocate (محدود بقيمة الدفعة)

الدرايف ─► POST /api/drive-sync   (تدريجي: يقارن المعرّفات ويضيف الفرق)
كشف مورّد ─► POST /api/statement-reconcile  (يكشف ما حُمّل ولم يصل)
```

## ٥. طبقة الخدمات

| الخدمة | المسؤولية |
|---|---|
| `document.service` | البصمة · إنشاء المستند · تسجيل التنبيهات |
| `invoice.service` | القيد · البنود وتسوية أسعارها · الكشوف |
| `validation.service` | إعادة الحساب على الخادم · قفل الشهر · المنع |
| `drive.service` | تفويض المستخدم · المجلدات · الرفع بلا استبدال |
| `payment.service` | الدفعات · التخصيص المحدود بقيمة الدفعة |
| `supplier.service` | التحميل · السياق · الإنشاء · تعلّم الأسماء |

الواجهات البرمجية تستقبل الطلب وتُترجم أخطاء الخدمات إلى رموز HTTP — لا أكثر.
كانت `api/archive` تحمل أربع عشرة مسؤولية في دالة واحدة.

## ٦. القاعدة

٢٠ جدولاً. المفاتيح نصّية (`randomUUID`). كل المبالغ `integer` بالهللات.
الشهر المحاسبي نصّ `YYYY-MM` مشتقّ من تاريخ الفاتورة لا تاريخ الرفع.

**الجداول الأساسية:** `users` `accounts` `sessions` `suppliers` `supplier_aliases`
`documents` `invoices` `invoice_lines` `statements` `statement_lines` `payments`
`payment_allocations` `bank_imports` `bank_transactions` `bank_rules` `issues`
`month_closes` `audit_logs` `schema_migrations`

### قيود تحمي المال

| القيد | ما يمنعه |
|---|---|
| `documents_sha_uniq` (جزئي، يستثني المحجور) | دخول الملف نفسه مرّتين |
| `bank_tx_external_uniq` | تكرار حركة بنكية عبر الاستيرادات |
| `bank_imports_file_sha_uniq` | تكرار سجلّ استيراد الملف نفسه |
| `invoice_supplier_number_uniq` | فاتورتان برقم واحد لمورّد واحد |
| `payment_allocation_uniq` | تخصيصان للفاتورة نفسها من دفعة واحدة |
| مشغّلات `audit_logs` | تعديل السجل أو حذفه أو إفراغه |

### حالات بدل الرايات

```
tax_status:        VALID | INVALID | UNKNOWN | NOT_APPLICABLE
input_vat_status:  ELIGIBLE | NOT_ELIGIBLE | UNKNOWN
tx_category:       SUPPLIER | SALARY | RENT | ZAKAT | UTILITY
                   | GOVERNMENT | PERSONAL | INTERNAL | OTHER | UNKNOWN
```

## ٧. الذكاء الاصطناعي: حدوده

| | |
|---|---|
| النموذج المستعمل | `gemini-flash-latest` (طبقة مجانية) — يُبدَّل بمتغيّر بيئة |
| ما يفعله | **نسخ** حقول المستند نصّاً، لا أكثر |
| ما لا يفعله | **لا يحسب شيئاً** · لا أدوات · لا وصول للقاعدة · لا وصول للدرايف |
| المخرجات | مقيَّدة بمخطّط، ثمّ تُفحص بـzod، ثمّ يعيد الخادم حسابها |
| الثقة الذاتية | **ليست حارساً** — رأيناه يخترع رقم فاتورة بثقة ١٫٠ |

كل حساب مالي في النظام يجري بـTypeScript محتوم. النموذج مُدخَل غير موثوق
مثله مثل المتصفّح.

> **تحذير قائم:** شروط الطبقة المجانية لجوجل تجيز استعمال البيانات لتحسين
> منتجاتها ومراجعتها بشرياً. اختيارٌ مؤقّت معلوم، وتبديله سطر واحد.

## ٨. الأوامر

```bash
npm run dev              # التشغيل المحلّي
npm test                 # اختبارات منطق الأعمال
npm run typecheck        # فحص الأنواع
npm run db:migrate       # تطبيق الهجرات
npm run db:audit         # تدقيق اكتمال البيانات وسلامتها
npm run db:repair        # إصلاح أعطال السلامة (بمعاينة أوّلاً)
npm run db:seed          # تأسيس سجل المورّدين
npm run drive:migrate    # ترحيل الأرشيف بأسماء ملفاته
npm run drive:backfill   # قراءة محتوى الملفات (مرّة واحدة)
npm run db:reprice       # إعادة حساب أسعار البنود
npm run db:merge         # دمج مورّد مكرّر
npm run db:repair-rules  # تعميم قواعد التصنيف
```
