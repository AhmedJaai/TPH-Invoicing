# نظام إدارة فواتير مؤسسة ذا بوبليك هاوس

تطبيق ويب يدير دورة الفاتورة من لحظة وصولها حتى قيدها وسدادها، مرتبطاً مباشرة
بأرشيف جوجل درايف القائم — دون تغيير بنيته ولا إعادة تسمية ملفاته.

**الرقم الضريبي:** ٣١٠٠٠٧٩٧١٦٠٠٠٠٣ · **السجل التجاري:** ٧٠٥٢٧٦٦٩٤١

---

## الرابط المباشر

**https://tph-invoicing.vercel.app**

يعمل من الآيفون والآيباد واللابتوب بلا تحميل شيء. ومن سفاري في الآيفون اضغط
زر المشاركة ثم «إضافة إلى الشاشة الرئيسية» ليصير أيقونة تفتح بملء الشاشة كالتطبيقات.

## مبدأ ثابت: الأرشيف لا يُمسّ

النظام **لا يحذف ولا ينقل ولا يعيد تسمية** أي ملف موجود في الدرايف.
أدوات المرحلة صفر كلها تطلب صلاحية **قراءة فقط**، فالكتابة مستحيلة تقنياً لا اتفاقاً.
ولا يبدأ الرفع إلا في المرحلة الأولى، وبتأكيد بشري في كل مرة.

## التشغيل السريع

```bash
npm install
cp .env.example .env     # ثم املأ القيم — راجع «إعداد جوجل» أدناه
npm run db:push          # ينشئ الجداول في قاعدة البيانات
npm run db:seed          # يؤسّس سجل الموردين
npm test                 # يشغّل اختبارات منطق الأعمال
npm run dev              # يشغّل التطبيق على http://localhost:3000
```

### الأوامر

| الأمر | ما يفعله |
|---|---|
| `npm run dev` | تشغيل التطبيق للتطوير |
| `npm test` | اختبارات قواعد التسمية والترتيب والصحة الضريبية |
| `npm run test:watch` | الاختبارات في وضع المراقبة |
| `npm run db:push` | مزامنة المخطط مع قاعدة البيانات |
| `npm run db:studio` | متصفح بيانات رسومي |
| `npm run db:seed` | تأسيس سجل الموردين (قابل للتكرار بلا ضرر) |
| `npm run drive:auth` | الحصول على مفتاح الدرايف — **قراءة فقط** |
| `npm run drive:auth -- --write` | الحصول على مفتاح بصلاحية الكتابة (للمراحل اللاحقة) |
| `npm run drive:inventory` | جرد الأرشيف وإخراج تقرير — قراءة فقط |
| `vercel deploy --prod` | نشر نسخة جديدة على الويب |

## إعداد جوجل خطوة بخطوة

تحتاج هذا مرة واحدة، ويستغرق نحو عشر دقائق.

### ١. أنشئ مشروعاً في Google Cloud

1. افتح [console.cloud.google.com](https://console.cloud.google.com).
2. من الشريط العلوي اضغط قائمة المشاريع ← **New Project**.
3. سمِّه `TPH Invoicing` ثم **Create**.
4. تأكّد أنه المشروع المختار في الشريط العلوي قبل أي خطوة تالية.

### ٢. فعّل واجهة الدرايف

1. من القائمة الجانبية: **APIs & Services ← Library**.
2. ابحث عن `Google Drive API` ثم افتحها واضغط **Enable**.

### ٣. اضبط شاشة الموافقة

1. **APIs & Services ← OAuth consent screen**.
2. اختر **External** ثم **Create**.
3. املأ: اسم التطبيق `فواتير ذا بوبليك هاوس` · بريد الدعم (بريدك) · بريد المطوّر (بريدك).
4. في صفحة **Scopes** اضغط **Add or Remove Scopes** وأضف:
   - `https://www.googleapis.com/auth/drive` — للقراءة والكتابة
   - `openid` · `email` · `profile` — للهوية
5. في صفحة **Test users** أضف بريدك وبريد المحاسب ومدير المشتريات.

> **مهم:** ما دام التطبيق في حالة **Testing** ينتهي مفعول الجلسة كل سبعة أيام
> ويُطلب تسجيل دخول جديد. لتفادي ذلك انشر التطبيق: **Publish App** من نفس
> الصفحة. ستظهر حينها شاشة «لم توثّق جوجل هذا التطبيق» — تتجاوزها مرة واحدة
> لكل مستخدم بالضغط على **Advanced ← Continue**. السقف مئة مستخدم، وهو أكثر
> من كافٍ لثلاثة.

### ٤. أنشئ بيانات الاعتماد

1. **APIs & Services ← Credentials ← Create Credentials ← OAuth client ID**.
2. النوع: **Web application**.
3. في **Authorized redirect URIs** أضف العنوانين معاً:
   - `http://localhost:3000/api/auth/callback/google` — لتسجيل الدخول
   - `http://127.0.0.1:53682/callback` — لأداة `drive:auth`
4. اضغط **Create** وانسخ **Client ID** و **Client Secret** إلى ملف `.env`:

```
GOOGLE_CLIENT_ID="..."
GOOGLE_CLIENT_SECRET="..."
```

### ٥. احصل على مفتاح الدرايف

```bash
npm run drive:auth
```

يفتح الأمر رابطاً في المتصفح، تسجّل الدخول بالحساب المالك للأرشيف، ثم يطبع
سطراً تضيفه إلى `.env`. الصلاحية الافتراضية **قراءة فقط**.

### ٦. جرّب الجرد

```bash
npm run drive:inventory
```

يمشي على الأرشيف ويخرج تقريراً بعدد الملفات وتصنيفها وما احتاج منها تدخلاً
بشرياً، ويحفظ نسخة كاملة في مجلد `reports/`. لا يعدّل شيئاً.

## بنية الأرشيف في الدرايف

```
My Drive / ACCOUNTS / 2026 / 2026-08 / Olive Leaves / <الملفات>
                                     / _إيصالات السداد
                                     / _نقدي - Cash receipts
                                     / _مرافق وحكومي - Utilities & Gov
                                     / _أخرى - Other suppliers
```

معرّفات المجلدات تُقرأ من متغيرات البيئة ولا تُكتب داخل الكود.

### قواعد التسمية

```
الفاتورة : YYYY-MM-DD_<الاسم المختصر>_Invoice_<رقم الفاتورة>_SAR<المبلغ>.pdf
الكشف    : YYYY-MM-DD_<الاسم المختصر>_Statement_SAR<المبلغ>.pdf
الإيصال  : YYYY-MM-DD_Receipt_<الاسم المختصر>[-<اسم المستفيد>]_SAR<المبلغ>.pdf
النقدي   : YYYY-MM-DD_Cash_<وصف>_SAR<المبلغ>.jpg
```

- المبلغ بمنزلتين عشريتين دائماً: `SAR410.00` لا `SAR410`.
- الصورة تحتفظ بامتدادها الأصلي ولا تُحوَّل.
- عند تكرار الاسم يُضاف ` (2)` — ولا يُستبدل ملف موجود أبداً.

**انتبه:** اسم المجلد يخالف الاسم المختصر غالباً. مجلد `Olive Leaves` ملفاته
باسم `OliveLeaves`، ومجلد `Golden Cup Factory` ملفاته `GoldenCup`. ولهذا
يحمل كل مورد الاسمين منفصلين في قاعدة البيانات.

### قواعد الترتيب

1. **الشهر = تاريخ الفاتورة، لا تاريخ السداد.** فاتورة ٢٩ أغسطس تذهب إلى
   `2026-08` ولو سُدّدت في سبتمبر.
2. **إيصال السداد يتبع شهر فواتيره لا شهر تحويله.** إيصال حُوّل ٢ سبتمبر عن
   فواتير أغسطس يذهب إلى `2026-08`.
3. **الفاتورة غير المسددة التي وصلت بعد كشف موردها تُرحَّل للشهر التالي**، مع
   حفظ شهرها الأصلي في الحقل `carriedForwardFrom` ليبقى الأثر مرئياً.

### قواعد الصحة الضريبية

الفاتورة صالحة لخصم ضريبة المدخلات فقط إذا حملت الأربعة معاً:
رقم فاتورة · الرقم الضريبي للبائع · الرقم الضريبي للمشتري مطابقاً لرقم المنشأة ·
تفصيل الضريبة.

ويضيف النظام فحصاً حسابياً يكشف أخطاء الاستخراج قبل القيد: المجموع يجب أن يساوي
الصافي زائد الضريبة، والضريبة تقارب ١٥٪ من الصافي.

وأي مبلغ يتجاوز ٣٬٠٠٠ ريال يُرفع كأصل ثابت محتمل يُرسمل ولا يُصرف. والأساس هو
الصافي حين تكون الضريبة قابلة للخصم، والمجموع حين لا تكون — لأن الضريبة غير
القابلة للخصم جزء من تكلفة الأصل.

## بنية الكود

```
src/
  config/drive.ts          معرّفات المجلدات وثوابت المنشأة — من البيئة لا من الكود
  db/schema.ts             نموذج البيانات كاملاً (١٨ جدولاً)
  db/index.ts              عميل قاعدة البيانات
  lib/money.ts             المبالغ بالهللات — لا فاصلة عائمة في المال إطلاقاً
  lib/naming.ts            بناء وتفكيك أسماء الملفات
  lib/filing.ts            قواعد الترتيب — أي شهر يذهب إليه كل مستند
  lib/validation.ts        فحص الصحة الضريبية والمحاسبية
  lib/issue-codes.ts       أكواد التنبيهات ونصوصها العربية
  lib/suppliers-seed.ts    سجل الموردين الابتدائي
  lib/drive.ts             طبقة الوصول للدرايف — لا دالة حذف فيها
scripts/
  drive-auth.ts            الحصول على مفتاح الدرايف
  drive-inventory.ts       جرد الأرشيف — قراءة فقط
  seed-suppliers.ts        تأسيس سجل الموردين
drizzle/sql/               هجرات SQL يدوية (إقفال سجل التدقيق)
```

### قرارات هندسية تستحق الشرح

**المبالغ أعداد صحيحة بالهللات.** لأن `0.1 + 0.2` في جافاسكربت لا تساوي `0.3`،
وخطأ «فاتورة بـ٣٬٤٠٠ قُيّدت ١٬٧٠٠» لا يجوز أن يتكرر من جهة النظام.

**سجل التدقيق غير قابل للتعديل ولا الحذف على مستوى قاعدة البيانات نفسها.**
ثلاثة مشغّلات ترفض `UPDATE` و `DELETE` و `TRUNCATE`. الاتفاق البرمجي وحده لا
يكفي لسجل يُفترض أن يصمد أمام المراجعة.

**مخرجات نموذج الاستخراج تُحفظ خاماً قبل أي تصحيح يدوي** في حقل
`extractionJson`، وثقة كل حقل على حدة في `fieldConfidence`. فما عُدّل يدوياً
يبقى قابلاً للمقارنة بما استُخرج آلياً.

## الواجهة والخط

الخط **ثمانية سانس** للنصّ و**ثمانية سيرف ديسبلاي** للعناوين، محمَّلان ذاتياً من
مجلد `src/fonts` بصيغة woff2 — فلا يعتمد التطبيق على خادم خطوط خارجي ولا يتأخّر
عرض النص العربي.

النظام اللوني أبيض وأسود خالصان بأعلى تباين، والرمادي للنص الثانوي والحدود فقط.
واللون محجوز للحالات وحدها — أخضر وكهرماني وأحمر — حتى يبقى التنبيه ملحوظاً
لأنه الملوّن الوحيد في الشاشة. والوضع الليلي يتبع إعداد الجهاز تلقائياً.

الواجهة مبنية للجوال أولاً، ومعها ملف `manifest.webmanifest` يجعلها تُضاف إلى
الشاشة الرئيسية وتفتح بملء الشاشة بلا شريط متصفح.

## النشر

التطبيق منشور على Vercel، ومتغيّرات البيئة مضبوطة على المشروع هناك لا في الكود.
لنشر نسخة جديدة بعد أي تعديل:

```bash
vercel deploy --prod
```

> **تنبيه على الخطة:** الحساب الآن على خطة Vercel المجانية، وشروطها للاستخدام
> الشخصي غير التجاري. قبل أن يصير النظام أداة العمل اليومية تحتاج الترقية إلى
> خطة Pro بعشرين دولاراً شهرياً، أو النقل إلى Firebase App Hosting كما في الخطة
> الأصلية — والنقل سهل لأن التطبيق لا يعتمد على شيء خاص بـVercel.

## الأمان

- لا مفتاح ولا سرّ داخل الكود. كل شيء في `.env`، وهو مستثنى من git.
- `.env.example` يحمل أسماء المتغيرات فقط بلا قيم حقيقية.
- أدوات المرحلة صفر بصلاحية قراءة فقط من الدرايف.
- الصلاحيات تُفرض على الخادم لا بإخفاء عناصر الواجهة: مدير المشتريات لا يصل
  إلى الأرقام المالية ولو استدعى الواجهة البرمجية مباشرة.
